# 01.6 — TUI Chat Rendering

## Objective

Replace the Node TUI chat log's fragile string-based rendering with a **message store + incremental renderer**, so streaming, markdown, thinking expand/collapse, click-to-copy, and history hydration all operate on first-class message objects instead of parsed display text. Upgrade the input from a single-line `textbox` to a multiline `textarea` with a prompt recall ring (↑/↓).

## Current State (before this plan)

- `tui/src/app.js` `appendChat`/`appendPart`/`removeLine` mutated `this.chatLog.getContent()` string state; `renderLastResponse()` re-parsed rendered lines with a `<Kamila>:...{/}` regex to find markdown zones.
- Message identity (who said what) was inferred by scanning rendered lines for `<You>` / `<Kamila>` / `<Agent>`.
- Streaming appended raw text per chunk and re-ran `renderLastResponse()` once at the end; a 200-chunk reply re-split the whole buffer every chunk.
- Thinking was tracked in `this.thinkingBlocks[]` / `this.activeThinking` and toggled by string-matching a header line.
- Click-to-copy and selection copy read `chatLog.getLine(i)` + `stripTags`.
- History was not restored on TUI launch; the input was a single-line `blessed.textbox`.

## Design

- **`tui/src/messages.js` — `MessageStore`**: append-only log of `Message` objects (`id`, `role`, `text`, `status` `streaming|done|error`, `kind` `text|thinking|tool|status`, `expanded`, `elapsed`, `model`, `label`). API: `add`, `addSystem`, `beginStream`, `find`, `remove`, `appendText`, `finish`, `last`, `lastOfRole`, `toggleThinking`, `clear`, `hydrate`, `list`, `count`.
- **`tui/src/renderer.js` — `ChatRenderer`**: per-message cache keyed by `id:status:expanded:kind`. A message whose `status === 'streaming'` is always re-rendered (text changes per chunk); done messages are cached. Returns `{ content, lineMap }` where `lineMap[i]` = message id of rendered content line `i`.
- **`tui/src/markdown.js` — `renderMessage(msg, {width, time})`**: single render entry point — builds the `[time] <Label>:` header, escapes/wraps user & system bodies, markdown-renders assistant/agent bodies, joins the first body line to the header, and appends a streaming `⟳` cursor or `(elapsed)` tag.
- **`tui/src/app.js` rewiring**:
  - `handleSubmit` adds a user message to the store, shows a `⟳ Thinking...` status message, and streams into a `beginStream('assistant')` message.
  - `setupStreamHandlers`: `onChunk` transitions thinking→response; `onThinking` maintains a collapsible `kind:'thinking'` message; `onToolCall`/`onToolResult` append tool messages. `finishStreaming` calls `store.finish(id)` (status → done) and invalidates the cache.
  - `renderChat()` renders the store to `chatLog` and stores `lineMap`.
  - `handleChatLogClick` resolves the clicked line via `lineMap` → message; thinking messages toggle expand/collapse, everything else copies the message text.
  - `copyLastResponse` copies `lastOfRole(['assistant'])` from the store.
  - `hydrateFromBridge()` calls `bridge.chatHistory('default')` on launch and `store.hydrate(rows)`.
  - Input is now a 3-row `blessed.textarea`; `C-o` inserts a newline, Enter sends; ↑/↓ (and C-p/C-n) cycle a prompt recall ring.
- **`src/bridge.jl`**: new `chat.history` handler returns `{ session, messages: [{role, content, created_at}] }` for the TUI to hydrate.
- **`tui/test/`**: `node:test` unit tests for `MessageStore`, `ChatRenderer`, and `renderMessage`, wired into `npm test`.

### Alternatives considered
- Keep string manipulation but add a line-map: still leaves markdown re-render and thinking toggling fragile; rejected.
- Store-only (no render cache): re-renders every message per chunk; the cache avoids O(n²) during streaming.
- Persist recall ring to disk: out of scope for 01.6 (simple in-memory array is sufficient).

## Acceptance Criteria

- [x] A streaming reply updates the active message per chunk without re-rendering the whole buffer (renderer cache; streaming always re-renders).
- [x] `lineMap` resolves every rendered content line to its message; clicking a line toggles thinking or copies that message's text.
- [x] Thinking streams into a collapsible `🧠 Thinking… (click to expand)` block; expand/collapse re-renders only that message.
- [x] `/copy` copies the last assistant message text from the store.
- [x] TUI hydrates persisted history from `chat.history` on launch.
- [x] Input supports multiline (`C-o`) and a prompt recall ring (↑/↓).
- [x] `chat.history` round-trip test passes; `npm test` green; Julia full suite green.
- [x] `/clear`, `/reset`, `/mode` reset the store + renderer cache.

## Risks & Mitigations

- **Risk:** Streaming messages cached frozen. **Mitigation:** renderer keys on `status === 'streaming'` and always re-renders those; app.js uses `beginStream()`.
- **Risk:** Recall-ring key handlers fight the textarea editor. **Mitigation:** `keypress` reset ignores navigation/control keys (`up`, `down`, C-p, C-n, enter, C-o).
- **Risk:** Hydration pulls a stale/empty session. **Mitigation:** `chat.history` keys on `Episodic.DEFAULT_SESSION` (`"default"`), matching where the bridge stores history.

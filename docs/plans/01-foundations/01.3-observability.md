# 01.3 — Observability

## Objective

Give Kamila structured, leveled, routeable logging so that debugging, the `memory_query`/`system_status` tools, and future learning plans can consume real data. Today the system prints ad-hoc text to stdout that is invisible when running as a bridge child process and useless for analysis.

## Current State

- Bare `println`/`println(stderr, ...)` scattered across modules: `src/bridge.jl:56,65,78,888-889`, `src/memory/memory.jl:54,70`, `src/ai/agent_stream.jl` (no logging), `src/system/monitor.jl` (none), `bin/kamila` (shell echoes).
- `src/bridge.jl:852 readline_timeout` and the JSON-RPC protocol use **stdout** for protocol traffic (`write_json` → `println(JSON.json(data))`); any `println` from a tool corrupts the protocol stream.
- No log levels, no timestamps, no log rotation, no structured fields.
- `.gitignore` doesn't reference a logs directory.

## Design

- Add a **`KamilaLog`** module (`src/system/log.jl`) with leveled logging: `debug`, `info`, `warn`, `error`, `fatal`; a global `LOG_LEVEL` env override (`KAMILA_LOG=debug`); and a sink that routes to **stderr** by default (never stdout, to protect the bridge protocol) with optional file sink (`KAMILA_LOG_FILE`).
- Structured output: log lines as `JSON` objects `{"ts": ..., "level": ..., "module": ..., "msg": ..., "fields": {...}}` when `KAMILA_LOG_FORMAT=json`, else human-readable.
- Replace the risky `println` sites in bridge/memory/tools with `KamilaLog`, keeping only protocol writes on stdout.
- Add a `context` (request id) for bridge handlers so a multi-step `ai.query` is traceable end-to-end.
- Optional file sink with simple size-based rotation (archive at 5 MB, keep 3).

# 01.1 — Test Infrastructure

## Objective

Replace the current mock-everything test suite with a test infrastructure that (a) tests real production modules against real file systems and real Ollama where possible, (b) uses strict, honest mocks only where the real dependency is external (network, GUI), and (c) gives fast, reliable feedback so later plans can prove their acceptance criteria as automated tests.

## Current State

- `test/runtests.jl` is the entry point; it only includes two files.
- `test/tools_test.jl` defines `MockKamilaEnv` that re-implements `FileAccess`, `KamilaMemory`, `TaskManager`, `SystemMonitor`, `OllamaInterface`, and `HTTP` as stubs, then `include("../src/ai/tools.jl")` into the mock namespace. The mocks are not the real code, so a breaking change in e.g. `TaskManager` is never caught.
- `test/agent_logic_test.jl` defines `MockAgentEnv` the same way for `agent.jl`.
- `test/security_check.jl` exists but is not referenced by `runtests.jl`.
- No fixtures, no temp-dir helpers, no coverage measurement, no way to run a single test target quickly.

## Design

- Keep the test file layout but add a **test runner** (`test/run.jl`) that supports `--target`, `--ci`, `--coverage`.
- Introduce **two mock tiers**:
  1. **Tier-1 / real**: modules that have no external side effects (parsing, path validation, task logic, memory logic with a temp `MEMORY_FILE`) are loaded directly from `src/`. Use Julia `Test` and `mktempdir()` for isolation.
  2. **Tier-2 / external**: only `HTTP` (web), `OllamaInterface` (model calls), `notify-send`, and TTS get mocks — behind a small seam (`Kamila.External` interface) so production code calls the seam, not the concrete function.
- Add a **MockServer seam** for `OllamaInterface`: the bridge/agent calls `OllamaInterface.query_ollama(...)`; provide a `test/OllamaMockServer.jl` that responds to `/api/generate` and `/api/chat` with canned streaming JSON, so agent-loop integration tests run without a real model.
- Add coverage via Julia's built-in `--code-coverage` and a `test/coverage.jl` script that prints per-file %.
- Provide `scripts/test.sh` wrapper: `test.sh` (all), `test.sh tools`, `test.sh agent`, `test.sh memory`, `test.sh --coverage`.

## Risks & Mitigations

- **Risk:** Tier-1 "real" tests hit the network (web_search) or GUI (`notify-send`). **Mitigation:** those stay behind the `Kamila.External` seam with canned mocks; network tests are opt-in (`--network`).
- **Risk:** Porting existing mocks is a large diff. **Mitigation:** keep the mock *shape* (module + function signatures) identical so production code doesn't change in this plan.
- **Risk:** CI runtime too long. **Mitigation:** target runner; CI runs full suite, local dev runs single targets.

## Objective

Learn and honor **user preferences** across responses, strategies, and tool-usage habits, so Kamila adapts its behavior to the person, not just to the prompt. This is "Adaptive" in the K.A.M.I.L.A acronym made real — while staying transparent and revocable.

## Current State

- Only static per-call knobs exist: `temperature`/`max_tokens` routed per task type (`src/ai/model_router.jl`), and a few hardcoded preferences like the personality string in `get_chat_system_prompt` (`src/ai/agent.jl:55-71`).
- `KamilaMemory` has no preference model; `usage_stats`/`productivity` are derived metrics (`src/memory/memory.jl:77-95`) unrelated to behavior preference.
- No explicit feedback capture (thumbs up/down), no implicit signal inference.

## Design (design-level; feedback channel + ranking is actionable)

- **Feedback capture:**
  1. Explicit: TUI adds 👍/👎 and a "why" (reply too long, too terse, wrong tone, wrong tool, or didn't do what I asked). Bridge route `feedback.record`.
  2. Implicit (opt-in, conservative): if the user edits/retries after an action, or marks a task complete immediately after a suggestion, treat as mild signal — never strong.
- **Preference store (`preferences` table + `preference_events`), Migration 10:**
  - `preferences(key TEXT PK, value TEXT, committed_default TEXT, source TEXT, ts)` — e.g. keys `tone=concise|narrated`, `verbosity`, `default_tool`, `confirm_threshold`.
  - Real values start from a baseline (`tone=narrated`), changed only by explicit feedback or a high-confidence implicit aggregate.
- **Inference (`src/learning/preferences.jl`):**
  - `update(key, delta)` — explicit feedback = strong (weight 1.0), implicit = weak (0.2).
  - Aggregator over window (e.g. last 30 events) picks the majority; flips only when a clear margin (min 5 relevant events) and a differing-confidence floor.
  - All changes are **logged with rationale** (`01.3`) and surface in `preferences` — never hidden.
- **Application:**
  - Inject active preferences into the system prompt via `03.4` as a small `# preferences` block (e.g. "user prefers concise answers; default to web=off").
  - `system_status`/daily-report verbosity mirrors preference.
  - Log when preference is applied so the user can see the cause-effect.

## Risks & Mitigations

- **Risk:** Overfitting to noise / chasing user mood. **Mitigation:** confirm window + threshold + revert UI.
- **Risk:** Implicit inference wrongly edits preferences. **Mitigation:** implicit signals default to nothing until a strong aggregate — and only for reversible fields.
- **Risk:** Preferences leak across sessions/users. **Mitigation:** namespace preferences by `session`/`user` from `Auth`.

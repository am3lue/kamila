# 07.2 — Local Fine-Tuning

**PROTOTYPE (2026-08-15)** — data pipeline + dry-run training job + eval
harness + gated promotion, fully testable without a GPU. `src/learning/`:
`tune/import.jl` (experience → chat exemplars, dedupe/cap/PII),
`tune/train.jl` (Modelfile + `ollama create`, dry-run default, never mutates
primary), `eval.jl` (functional-success gate, deny-class regression guard),
`tune/promote.jl` (gated ModelRouter merge, `enabled=false`). Producing the
actual LoRA `.gguf` is out of scope (see `tuning-notes.md`). Tests:
`test/eval_test.jl` (48). Full suite 4664 pass / 2 broken.

## Objective

Build a **local fine-tuning pipeline** that turns curated experience (`07.1`) and skill procedures (`05.2`) into updated `gpt-oss`-family weights via Ollama, so Kamila improves at the specific tasks/language it actually does — fully on-device, no cloud.

**Status flag:** This is *design-level + prototype*, not a shipped commitment. LLM fine-tuning quality/eval is open research; success must be measured, not assumed.

## Current State

- The model is `gpt-oss:120b-cloud` from `config/Modelfile` (a 120B cloud-scale model — impractically large for local fine-tuning on consumer hardware).
- `setup_kamila_model` (`src/ai/ollama_interface.jl:381-401`) only runs `ollama create` with the Modelfile; no training path.
- No datasets, no eval harness, no fine-tune orchestration (`ollama` supports `ollama create -f Modelfile` with `ADAPTERS`/LoRA for QLoRA fine-tuning).

## Design

- **Reality-check gate:** default target is a *small* local model for fine-tuning (e.g. `qwen2.5-coder:0.5b` already a fallback in `src/ai/model_router.jl:74`), not the 120B. Two stacks:
  - **Inference** (`gpt-oss:120b-cloud`, cloud/high-resource) stays default for general chat via `03`.
  - **Fine-tunable** (small local model) is what we actually fine-tune and can fall back on for narrow, repeated tasks.
- **Data pipeline (`src/learning/tune/import.jl`):**
  - Export `07.1` records with `verified=true` → pairs.
  - Convert to chat format for LoRA adapters: `{system, user → assistant}` pairs, with the tool-call/step sequence placed in `assistant` content; then dedupe and filter by quality heuristics (length, verification, no-PII heuristic).
  - Cap dataset (e.g. ≤2,000 examples) for first pass; add curation (random sample + user-inspected subset).
- **Training job (`src/scripts/tune/run.jl`):** wraps the Ollama `create` with a `Modelfile` (`FROM <base>` + LoRA adapter, reusing existing `PARAMETER`s); runs QLoRA if hardware supports it (detected via nvidia-smi / Ollama GPU flag). Job output is captured to a log for review.
- **Evaluation harness (`src/learning/eval.jl`):**
  - Hold-out set from experience-not-in-training.
  - Metrics: task success (tool-result verified), response quality proxy (rouge/bleu optional; primary = functional success `check_ok`), latency.
  - A/B: before/after adapter on same hold-out — only promote new adapter if functional-success improves ≥ threshold (e.g. +5 pts) and no regression on safety holds (deny-class prompts).
- **Promotion:** success → save adapter as a named skill/model config in `ModelRouter`; user can review. Failure → keep prior, log metrics.

## Acceptance Criteria

- [x] A curated export produces a valid, capped, deduped JSONL dataset.
- [x] Training job invocation is safe (dry-run flag; never mutates the primary model).
- [x] Eval runs base vs adapter on a holdout and gates promotion on functional-success, not just loss.
- [x] Defending against regression: adapter that lowers deny-class success is not promoted.
- [x] Everything runs locally; no cloud calls in the pipeline.

## Risks & Mitigations

- **Risk:** Fine-tuning small models yields no real gain / degrades. **Mitigation:** eval-first; promotion only on measured +5 pt functional improvement; revert path documented.
- **Risk:** Hardware can't do the work. **Mitigation:** pipeline runs even with no adapter (data prep + eval still validated); tuning is opt-in button, not automatic.
- **Risk:** Overfitting chat-mirror of the 13 tools on the shell. **Mitigation:** eval include held-out task types + deny-set; cap dataset size aggressively.
- **Risk:** "AGI" narrative creep. mitigation: name it explicitly as task-specialized adapter for limited, low-risk tasks.

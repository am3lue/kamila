## Hypothesis (testable claim)

A lightweight, learned **outcome predictor** — "if I run this tool with these args, what state change occurs?" — can improve planning (`04`) by rejecting steps whose predicted outcome violates invariants before executing them, reducing wasted/dangerous actions.

## Prior art to survey

- World models for planning: Ha & Schmidhuber World Models, Dreamer/MuZero-style abstract models.
- Tool-outcome prediction for safe agents (predicting tool effects from experience).
- Invariant-based safety: model checkers on state-transition abstractions.

## Sketched approach

1. **Data:** reuse `07.1-experience-store` verified tool outcomes — `(tool, args, post_state diff)` triples.
2. **Model:** a small LLM (or structured regression) `P(post_state | tool, args, pre_state)` projected onto a small schema of invariants: files changed, exit code, dir contents, task rows.
3. **Use:** in `04.3-verification-loop`, before executing a step, run the predictor; if the predicted outcome violates a declared invariant, escalate/abort early.

## Cost & risks

- Cost: small — reuse experience data; an extra model call per step (cacheable).
- Risks: predictors hallucinate; a bad predictor could veto safe actions. Mitigation: predictions only *raise* a flag for human/model review; never auto-deny without `:permission` gate.

## Go/no-go rubric

- **Go:** predictor beats random on a held-out set of tool outcomes by > 20 pts, and false-veto rate on safe steps < 2%.
- **No-go:** otherwise, keep `04.3` verification as the only check.

- **Prototype:** `module OutcomePredictor` in `src/research/outcome_predictor.jl`. It is an **exact-key nearest-example** model: it predicts an outcome only for a `(tool, args)` pair it has seen before (canonical sorted-args key, control keys excluded) — it NEVER guesses on unseen pairs. `evaluate(samples)` computes coverage, accuracy, a majority-class baseline, the accuracy−baseline delta, and the **false-veto rate** (fraction of covered-safe calls the predictor marked failed) — exactly the quantities the rubric needs. Data plumbing: `load_experience_samples()` reads the `07.1` experience store (verified flag preserved).

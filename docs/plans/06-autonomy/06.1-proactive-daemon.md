# 06.1 — Proactive Daemon

## Objective

Give Kamila a persistent **background lifetime** so it can react to events, run scheduled checks, and initiate notifications/actions — without the TUI being open. Today Kamila exists only while `bin/kamila`/`run_bridge` runs and only acts in response to a request (`src/bridge.jl:870-893`); `set_reminder` (`src/ai/tools.jl:576-602`) is the *only* proactive behavior and it is fire-and-forget `notify-send`.

## Current State

- Single process, request/response only. No background loop, no event source, no persistence of scheduled jobs.
- `set_reminder` spawns `sleep ... && notify-send` (`src/ai/tools.jl:588-594`) — dies with the process, no retry, no reschedule, no audit.
- `get_system_alerts` (`src/system/monitor.jl:448-482`) computes alerts but nothing watches them over time.
- No daemon entry point exists; `bin/kamila --bridge` is interactive (`readline_timeout` loop).

## Design

- **Daemon mode:** `bin/kamila --daemon` starts `Daemon.run()`:
  - Detaches from TTY (optional `--no-detach` for testing), writes `pid` file (`$XDG_STATE_HOME/kamila/daemon.pid`), logs to file (`01.3`).
  - Owns the SQLite DB connection long-lived (`03.1`).
  - Runs a **main loop** (tick every 1 s) dispatching: timer events, filesystem watchers, and polled monitors.
- **Job scheduler:** persisted `scheduled_jobs` table (Migration 6) — `{id, kind, spec, next_run_at, interval, last_status}`. Kinds:
  - `reminder` (migrate `set_reminder` to persist here; deliver via `notify-send`, and if TUI attached, a `notification` event).
  - `check` (run `system_status` / alerts; raise a notification when health score drops below threshold — with debounce, e.g. once per hour).
  - `daily_report` (the `generate_daily_report` from `src/system/monitor.jl:347-418` / task report `src/tasks/task_manager.jl:274-309`) at a configurable time.
  - `web_poll` (optional; e.g. watch a URL for changes — research-grade, gated).
- **Event bus:** `src/system/events.jl` — `publish(event)` / `subscribe(pattern, handler)`; daemon loop consumes a queue. Bridge (`run_bridge`) also subscribes when running so the TUI receives daemon-sourced notifications live.
- **File watcher:** optional inotify watch on the allowed dirs (`src/Kamila.jl:10`) to emit `file.created/updated` events (bounded, opt-in, config `daemon.watch_dirs`).
- **Graceful shutdown:** SIGTERM/SIGINT → flush scheduler, close DB, stop loop; restart-safe (jobs with `next_run_at` in the past run immediately on boot — catch-up mode).

## Acceptance Criteria

- [x] A scheduled reminder survives a daemon restart and still fires.
- [x] Boot catch-up runs overdue jobs exactly once (no double-fire).
- [x] Health-score threshold triggers at most one notification per debounce window.
- [x] Daemon runs headless (no TTY) and TUI attached later still receives live notifications.
- [x] Shutdown is clean: no orphan processes, DB consistent, pid file removed.
- [x] No permission bypass: all daemon-initiated actions still pass `02.2`/`05.3` policy (headless `:ask` resolves to `:deny` + logged).

## Risks & Mitigations

- **Risk:** Daemon acting without consent. **Mitigation:** every daemon action resolves through `Permission.evaluate`; headless `:ask` → deny with audit; the *only* automatic notifications are informational (reminders, health).
- **Risk:** Resource leaks (watchers, timers). **Mitigation:** bounded watcher count, timer cleanup on cancel, CI leak test.
- **Risk:** DB contention between daemon and bridge. **Mitigation:** `03.1` WAL + single-writer lock; bridge connects as a second reader when daemon owns the writer.

## Implementation Notes (2026-08-15)

- **Modules added:** `src/system/events.jl` (`Events` — bounded event queue, prefix `subscribe`/`unsubscribe`, synchronous dispatch in publish order), `src/system/scheduler.jl` (`Scheduler` — persisted CRUD + `run_due!` catch-up), `src/system/daemon.jl` (`Daemon` — `run()` main loop, pid file, `tick_once`).
- **Migration 6** adds the `scheduled_jobs` table; `SCHEMA_VERSION` bumped to 6.
- **Signal handling:** Julia 1.12's runtime owns SIGTERM/SIGINT; `jl_register_signal` no longer exists. Cleanup (pid file + DB close) is registered via `atexit` (verified to run on SIGTERM) plus the loop's `finally`.
- **Headless consent:** `_deliver_job` resolves every action through `Permission.evaluate`; `:ask` → `:deny` + logged, never a TTY prompt. `set_reminder` is `:allow` in the starter policy (informational).
- **`set_reminder`:** delayed reminders now persist via `Scheduler.create_job` (survive restart); instant (delay 0) reminders still `notify-send` immediately.
- **Bridge:** `run_bridge` subscribes to the event bus; informational kinds (`notification`, `health.alert`, `file.created/updated`) forward as `notification` protocol events for the TUI.
- **CLI:** `bin/kamila --daemon` (detaches via `setsid`, verified end-to-end: start → status shows pid → SIGTERM stop → pid file removed), `--daemon-status`, `--daemon-stop`. `--no-detach` runs in-process (used by tests). Note: `Daemon.run` shadows `Base.run` inside the module — detach/notify use `Base.run` explicitly.
- **Health check:** reads `is_healthy.score` (not a top-level `health_score`); fires `health.alert` when below threshold.
- **Tests:** `test/daemon_test.jl` (50 tests, target `daemon`) — event order, catch-up-once, one-shot delete, restart persistence, headless deny, pid-file lifecycle, bridge forwarding. Full suite: **4447 pass / 2 broken** (broken = pre-existing lint `@test_skip`s).
- **Caveats:** the debounce window is enforced by the interval itself (a repeating `check` job fires at most once per interval; catch-up runs a missed run once). No inotify file watcher yet (optional, `daemon.watch_dirs` deferred). `_pid_alive` probes with `ccall(:kill, Cint, (Cint,Cint), pid, 0)` because `Base.kill` expects a `Process`, not a raw pid.

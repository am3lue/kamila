# 03.4 — Context Injection

## Objective

Replace the hardcoded context block in `inject_memory_context` (`src/bridge.jl:235-265`) with a **context selector** that builds the system prompt from the most relevant memories, plans, goals, and recent conversation for the *current* query — bounded by token budget, with clear provenance labels.

## Current State

- `inject_memory_context` unconditionally appends active goals + pending tasks + today's achievements to the chat system prompt (`src/bridge.jl:235-265`).
- No query-awareness: the same context is injected for every message regardless of topic.
- No token budget: if the user has 200 tasks, all are dumped in.
- Chat history is appended wholesale (`src/bridge.jl:305-307`), ignoring relevance.

## Design

- **Context assembler** `src/memory/context.jl`:
  - Inputs: `(query, mode, session)`.
  - Sources, each a pluggable provider returning `(priority, est_tokens, text, label)`:
    - `EpisodicProvider` — top-k day/week summaries via `03.2` recall, decayed.
    - `MemoryProvider` — top-k semantic recalls for the query.
    - `GoalProvider` — active goals only when query relates (keyword/semantic gate).
    - `TaskProvider` — pending/overdue tasks, capped (default 10, sorted by priority).
    - `PlanProvider` — current active plan steps (from `04.1`, when present).
    - `HistoryProvider` — recent turns, but **ranked by relevance** via embeddings, not just recency (when `memory.embed` on).
  - **Budget:** target default 2,000 tokens of context (config `memory.context_budget`). Greedy pack by priority then recency; truncate lowest-priority sources first; a hard cap (e.g. 3,000) never exceeded.
  - **Provenance:** each injected block is wrapped with a label (`# [memory: episodic-summary (score 0.61)]`) so the model (and user) can see why it's there; no unlabeled dumping.
- **System prompt contract:** return the full system prompt string; keep the base `get_chat_system_prompt` intact, context appended.
- **Session-boundary correctness:** history for the *current* session only (fixes the current global `chat_messages` default-session behavior where sessions share history — `src/bridge.jl:49-54`).

## Risks & Mitigations

- **Risk:** Over-injection bloats prompts and increases latency/cost. **Mitigation:** budget + priority packing; measure average injected tokens in `01.3` and surface in a log line.
- **Risk:** Semantic gating misfires (relevant task omitted). **Mitigation:** task/goal providers use a *gate* but always keep top-3 by priority as safety floor.
- **Risk:** Session-scoping change surprises existing TUI. **Mitigation:** default session id unchanged (`"default"`); only new explicit sessions get isolation.

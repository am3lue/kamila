# 03.2 — Embeddings & Retrieval

## Objective

Give Kamila **semantic** recall: given any query, retrieve the most relevant memories/conversations/documents even when they share no keywords. This replaces the "dump whatever is in the JSON" behavior with genuine relevance search, and it is the primitive `03.4-context-injection` uses to build prompts.

## Current State

- No embeddings anywhere. `memory_query` only supports fixed keywords (`summary`, `achievements`, `goals`, `productivity`) and reads fields directly (`src/ai/tools.jl:606-670`).
- No vector store; no way to ask "what have I worked on this week?" and get an answer from content.
- `web_search` exists but is external; local semantic recall does not.

## Design

- **Embedding provider:** Ollama embeddings API (`POST /api/embed`, e.g. model `nomic-embed-text` or `mxbai-embed-large`), wrapped behind a `Vectors` module seam (`src/memory/vectors.jl`) so the provider can be swapped. Default model configurable via `~/.kamila_config.json` → `memory.embed_model`.
- **Storage:** a `memories` table in SQLite (`03.1`) with columns: `id`, `kind` (`chat`/`task`/`goal`/`note`/`document`), `content`, `created_at`, `importance` (0–1), `embedding BLOB` (float32 array). Plus a `recall_log` for debugging what was retrieved.
- **Index:** in-memory brute-force cosine over the table is fine for ≤50k rows; document that this becomes HNSW only if/when the corpus grows past that (research in `09`). Cache embeddings by content hash to avoid re-embedding.
- **API:**
  - `Vectors.embed(text) -> Vector{Float32}`
  - `Vectors.similarity(a, b) -> Float64`
  - `Memory.remember(content; kind, importance)` — stores + embeds.
  - `Memory.recall(query; k=5, kinds=nothing, min_sim=0.25) -> Vector{MemoryHit}` where `MemoryHit` has `.content`, `.kind`, `.score`, `.created_at`.
- **Keyword fallback:** if the embedding endpoint is unavailable, fall back to SQLite FTS5 (add FTS5 virtual table over `memories.content`) and log the degradation (`01.3`). Never silently return nothing when content exists.
- **Background embed:** on startup, lazily embed existing chat/task content in batches (bounded, e.g. 50/batch, throttled) so historical data becomes recallable without blocking first interaction.

- [x] `memory_query search` works through the bridge and TUI.

## Risks & Mitigations

- **Risk:** Embedding model not pulled locally. **Mitigation:** `setup_kamila_model` also pulls the default embed model; fallback path documented.
- **Risk:** Recall quality poor on tiny model. **Mitigation:** min_sim threshold + k limit; importance-weighted ranking; provider swappable.
- **Risk:** Privacy (embedding all chat). **Mitigation:** embeddings stored locally only; `delete_memory` removes both row and cached vector; opt-out via `memory.embed=false` config.

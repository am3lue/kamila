# 04.3 — Verification Loop

## Objective

Make "Check" an **enforced** phase, not a prompt suggestion. Every plan step that performs a side effect must be verified against its expected outcome before it can be marked `:verified`; unverifiable or failed verification triggers re-planning or rollback. This directly answers the AGI-assessment gap of "no enforced check" (`../AGI_ASSESSMENT.md` §3.5).

## Current State

- The system prompt *suggests* a `Read -> Analyze -> Execute -> Check` framework (`src/ai/agent.jl:31`) but nothing enforces it; `src/ai/agent.jl:37` even says "You can skip the 'Check' phase if the tool output is definitive".
- Tool results are strings; nothing compares them to an expectation.
- No undo/rollback mechanism exists (`write_file` has no revert, `run_shell_command` is fire-and-forget unless the agent manually compensates).

## Design

- **Verification contract per step** (`04.1.PlanStep` gains optional `verify`):
  ```julia
  verify::Union{Nothing, VerifySpec}
  # VerifySpec:
  #   kind = :file_exists | :file_contains | :file_matches_regex | :command_ok |
  #          :shell_output_contains | :shell_output_matches | :status_code | :schema | :model_judgement
  #   target = string (path or command or expected value)
  #   timeout, retries
  ```
- **Verifier** `src/planning/verify.jl`:
  - Executes the `verify` spec against the post-condition of the step.
  - `:model_judgement` calls the model once with a short prompt (tool result + expected outcome) — used when no deterministic check fits.
  - Returns `VerifyResult(ok::Bool, evidence::String, duration_ms)`.
- **Loop wiring:** after a step's tool result arrives:
  1. If a `verify` spec exists, run it (deterministic kinds first; `:model_judgement` only when deterministic unavailable).
  2. `ok` → step `:verified`, advance.
  3. `not ok` → step retries (attempts < max) with the evidence fed back to the model so it can self-correct (`:retryable`), else step `:failed` → **rollback path**.
- **Rollback:** `src/planning/rollback.jl` registry of inverse actions:
  - `write_file` with `create_backup=true` (`src/ai/tools.jl:165-168`) → restore `.bak`.
  - `run_shell_command` in an allowed `undo_command` rule (`02.2` policy) → run inverse.
  - Otherwise, log `:internal` warn ("no rollback defined for X") and surface to the user rather than silently continuing.
- **Escape hatch:** verification is skipped only when the step declares `verify=nothing` *and* the tool result is structurally definitive (e.g. `add_task` returns the created task id). This must be justified in the plan step, logged.

## Acceptance Criteria

- [x] A `write_file` step whose file content doesn't match the verify spec fails → retry → (attempts exhausted) → rollback restores prior content.
- [x] A `run_shell_command` step with `verify=:command_ok` requires exit code 0.
- [x] `:model_judgement` verification is used only when no deterministic check applies.
- [x] Skipping verification requires `verify=nothing` and is logged with justification.
- [x] No regression on happy-path steps that already pass.

## Risks & Mitigations

- **Risk:** Over-verification slows the agent and increases model calls. **Mitigation:** default verify specs for write/delete/shell tools; cheap deterministic checks preferred; `:model_judgement` throttled (max 1 per step).
- **Risk:** Rollback actions themselves are dangerous. **Mitigation:** rollback only for steps that declared backup/undo at execution time; rollback itself goes through `02.2` permission policy; never auto-rollback destructive commands without user consent.

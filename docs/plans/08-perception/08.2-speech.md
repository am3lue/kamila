# 08.2 — Speech (Speech-to-Text)

## Objective

Add a **speech-to-text tool** so Kamila can accept voice input, complementing the existing text-to-speech output (`src/ai/tts.jl:66-102`). Works headless (via the `06.1` daemon / bridge) so audio can be transcribed and acted upon.

## Current State

- `TTS.speak` writes text → audio (piper → spd-say → espeak fallbacks, `src/ai/tts.jl:78-101`). Input direction is absent.
- No microphone capture, no audio file handling, no STT dependency.
- `docs/KAMILA_MANUAL.md` references voice output conceptually but nothing records audio.

## Design

- **STT backends (priority order), behind `src/system/stt.jl` seam:**
  1. Ollama whisper (`whisper:large-v3-turbo` or similar) via `/api/generate` on audio bytes — truly local, no cloud.
  2. `whisper.cpp` (`whisper-cli`) if installed.
  3. `vosk` CLI if present, else explicit `:external` unavailable error.
- **New tool** `transcribe_audio(file_path) → {text, confidence?}`:
  - Validates path; accepts `.wav`, `.mp3`, `.ogg`, `.flac`; MIME/extension check.
  - Converts to 16 kHz mono wav for the model (ffmpeg if available; else raw passthrough).
  - Returns recognized text (and optional per-word timestamps for alignment).
- **Live capture (bridge/daemon):** optional block `audio.record` that records N seconds from microphone via `arecord`/`parecord`, saves to a temp wav in allowed dirs, then transcribes. Gated `:ask`.
- **Integration:** transcribed text is injected as a user message into `handle_ai_query` (`src/bridge.jl:284`), so voice → Kamila action uses the normal pipeline. `TTS.speak` already exists for the reply-side.
- **Draft flag:** transcription includes a confidence flag; TUI shows the recognized text for correction before sending (since local STT isn't perfect).

## Acceptance Criteria

- [ ] `transcribe` returns text for a fixture audio file via the mock backend.
- [ ] Unsupported format → `:validation` error.
- [ ] No STT backend → `:external` error, no hang/crash.
- [ ] Transcribed text appears as a user message in-conversation.
- [ ] Recording a clip (mocked `arecord`) yields a sendable draft.

## Risks & Mitigations

- **Risk:** Whisper models are large for local. **Mitigation:** backend gating; optional install; `transcribe` still works headless on existing files.
- **Risk:** Privacy of microphone audio. **Mitigation:** default `:ask` permission before recording; temp files in a gitignored dir; no cloud; clear post-recording deletion.
- **Risk:** Bad transcription. **Mitigation:** draft-and-confirm UI + confidence flag.

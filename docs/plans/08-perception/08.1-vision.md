## Objective

Add a **vision tool** so Kamila can interpret images: `describe_image(path)` and `answer_question_about_image(path, question)`. This is the first perceptual modality beyond text and is the foundation for `08.3-desktop-awareness`.

## Current State

- No image handling anywhere. `read_file` explicitly rejects binary files (`src/ai/tools.jl:95-97` "Cannot read binary file").
- `is_text_file` only checks for null bytes (`src/ai/tools.jl:125-135`) — no MIME/extension awareness.
- The model stack is text-focused: `config/Modelfile` has no vision tags, though `ModelRouter.MODEL_TYPES` already lists `:vision` (`src/ai/model_router.jl:20`) — currently unused.

## Design

- **Vision model:** a dedicated Ollama vision-capable model (e.g. `llava` or `llama3.2-vision`). Route via the existing `:vision` task type in `ModelRouter` (add a default `ModelConfig` entry).
- **New tool** `vision` (in `AgentTools`):
  ```json
  {"tool": "vision", "args": {"file_path": "...", "task": "describe | qa", "question": "..."}}
  ```
  - Validates path via `FileAccess.validate_path` (must be in allowed dirs).
  - Accepts `.png/.jpg/.jpeg/.gif` (MIME check, not just extension).
  - `describe` → model summary; `qa` → answer to the question about the image.
- **Protocol:** Ollama `/api/chat` with `images` field (`images: [base64]`). Size guard: reject images > 10 MB; downscale with `sips`/ImageMagick if available (graceful skip if not).
- **Integration:**
  - `describe_image` also usable inside a plan step (`04`) via `verify.kind = :image_contains` (asks the model "does the image contain X?").
  - Results stored as a `memories` row `kind="image"` with the description text (`03.2` recallable).
- **Fallback:** if no vision model is available, tool returns a categorized `:external` "vision model unavailable" error (`01.4`), never a hallucinated guess.

## Risks & Mitigations

- **Risk:** Vision model unavilable → tool useless. **Mitigation:** graceful `:external` error; setup script offers optional vision model pull.
- **Risk:** Privacy (images of user's screen). **Mitigation:** images only read from allowed dirs; `vision` tool permission-gated (`:ask` by default in `02.2` policy); no cloud.
- **Risk:** Latency of large images. **Mitigation:** downscale + size cap; streaming description tokens via existing chat stream.

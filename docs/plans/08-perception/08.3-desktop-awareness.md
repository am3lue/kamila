# 08.3 — Desktop Awareness

## Objective

Give Kamila **context about the current desktop session**: the active window, the focused application, the terminal/cwd, and (optionally) a screenshot — so it can answer "what am I working on?" and assist with what the user is looking at. This depends on `08.1-vision` for screenshot meaning and on `06.1` for a persistent watcher.

## Current State

- No awareness of the user's current activity. `system_status` only reports OS/shell telemetry (`src/system/monitor.jl`).
- No window/clipboard utilities. `set_reminder` uses `notify-send` (`src/ai/tools.jl:576-602`) but nothing inspects the desktop.
- `allowed paths` are fixed dirs (`src/Kamila.jl:10-14`); nothing captures screenshots.

## Design

- **New tool** `desktop_status` (`src/system/desktop_context.jl`), returning a JSON snapshot:
  - `active_window_title`: via `xdotool getactivewindow getwindowname` (X11) or `gdbus`/`swaymsg` (Wayland) — feature-detected.
  - `cwd`: current working dir from the daemon/bridge (if it persists).
  - `clipboard`: contents (via `xclip`/`wl-paste`), truncated (e.g. 4 KB).
  - `keyboard_focus_app` (best-effort).
- **Screenshot (`visual_context`):** optional, gated `:ask`: captures screen `import -window root`/`grim`, `08.1` describes it. Returns the *description*, not the image, to the agent (privacy). Only if vision available.
- **Watcher (`desktop.watch`):** optional poll (every N s) emitting `desktop.activity` events on the bus (`06.1`), so the daemon can offer proactive hints ("I see you're in a terminal, want me to check for build errors?").
- **Privacy posture:** all desktop-context features are **off by default**; enabled per-user with `:ask` permission policy; screenshot capture is prompt-on-each and described-only-upstream.
- **STT/Vision tie-in:** `desktop_status` returns `active_window` that STT `transcribe` can annotate (`08.2`); screenshot → `08.1` describes.

## Acceptance Criteria

- [ ] `desktop_status` returns active window/cwd/clipboard when tools available; degrades gracefully (not crash) otherwise.
- [ ] Clipboard is redacted other than basic text; no secrets-sticking values logged.
- [ ] Screenshot → vision description, image never put in the prompt (privacy).
- [ ] `desktop.watch` off by default; enabling requires user consent and emits `daemon.activity` events.
- [ ] Screenshot capture permission prompt before each; the user sees what Kamila sees.

## Risks & Mitigations

- **Risk:** Desktop context is invasive. **Mitigation:** default off, `:ask` always, non‑persisted image, no automated screenshot without an opt-in and log every capture.
- **Risk:** Wayland (sway/spawn) has no window names. **Mitigation:** nice `—unavailable`, not a failure; document the restriction.
- **Risk:** Clipboard leakage. **Mitigation:** redact clipboard to first 4K; only shown in local TUI, never sent to a server.

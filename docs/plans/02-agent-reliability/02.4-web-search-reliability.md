# 02.4 — Web Search Reliability

## Objective

Replace the fragile DuckDuckGo HTML string-scraping search with a stable, structured, rate-limit-aware search implementation, plus a clean seam so the search backend can be swapped without touching agent code.

## Current State

- `web_search` (`src/ai/tools.jl:396-441`) does `HTTP.get("https://html.duckduckgo.com/html/?q=...")` then `split(html, "class=\"result__body\"")` and regex-extracts `href`/title/snippet from the HTML blocks.
- Failure modes: (a) DDG returns a bot-check/redirect page → 0 results or garbage; (b) HTML structure change breaks parsing silently; (c) no rate limiting → 429s; (d) `HTTP.escapeuri` mismatch with DDG's expectations; (e) results include tracking/redirect URLs.
- Only the bridge-visible tool surface is `web_search(query, max_results)`; the implementation detail is entangled with DDG.

## Design

- **Backend seam:** new `Search` module (`src/system/search.jl`) exposing `search(query; max_results=5)` returning `Vector{Dict(:title,:url,:snippet)}` or `nothing` on failure.
- **Backends:**
  1. **DDG lite** (`https://lite.duckduckgo.com/lite/`) as the default — lighter HTML, more stable markup; parse with a small HTML tag stripper rather than fragile class-splitting.
  2. **Seamless alt:** a generic `:custom` backend read from config (`~/.kamila_config.json` → `search.backend`, `search.endpoint`, `search.api_key`) so users can point at a Brave/Serper/etc. endpoint later without code changes.
- **Parsing:** HTML → text via regex-based tag stripping (documented, tested against fixtures), then extract result blocks by anchor + snippet proximity. No reliance on `class="result__body"`.
- **Rate limiting:** token bucket (default 1 req / 1.5 s, burst 5) in `Search`. On 429/timeout → return `nothing` with `:rate_limited` category (`01.4`), *never* a half-parsed page.
- **URL hygiene:** strip `//duckduckgo.com/l/?uddg=` redirect wrappers; return the destination URL. Cap snippet length at 300 chars.
- **Caching:** in-memory LRU (max 200) keyed by query+max_results, TTL 10 min — reduces rate-limit pressure during agent loops.

## Acceptance Criteria

- [x] `web_search` returns clean destination URLs (no `uddg=` wrappers).
- [x] A bot/redirect page returns a categorized `:rate_limited`/`:external` error, not 0 fake results.
- [x] Consecutive calls within the rate window are throttled (token bucket test).
- [x] Cached identical queries within TTL don't hit the network (spy count test).
- [x] Backend switchable via config with zero agent-code changes.

## Risks & Mitigations

- **Risk:** DDG-lite markup still changes. **Mitigation:** fixtures make changes visible in CI; parsing uses structural heuristics (anchors/links order) not opaque class strings.
- **Risk:** Search backend rate-limits Kamila. **Mitigation:** conservative token bucket + cache; graceful `nothing` rather than retry storms.
- **Risk:** Custom backend API key stored in config. **Mitigation:** read from env `KAMILA_SEARCH_KEY` first; never log it (ties into `01.3` no-secrets rule).
